# reg_meta_build curation surface inventory

R0 for #518, tracked by #519. This is an inventory and charter only. It does not propose
compatibility shims: the workspace is pre-v1, so later child work can change the current
files and loaders directly.

This file is a temporary R0 artifact, not a permanent package tracker. Delete it when
#518's durable decisions have moved into `reg_meta_build/DESIGN.md` and the remaining
work is represented by native GitHub child issues.

Disposition terms used below:

- `keep`: leave as its own surface.
- `delete/reverse`: remove the behavior, or reverse it into less invasive authoring,
  once an equivalent user-facing contract exists.
- `migrate to relations`: move pairwise graph facts into an explicit typed relation
  surface.
- `migrate to a set subtype`: keep collection semantics, but make the subtype explicit
  rather than pretending every set is the same thing.
- `share helpers only`: keep the surface separate; extract only boring parser,
  validation, or traversal code if it pays for itself.
- `defer`: leave unchanged until a narrower child proves a real deletion or cleanup.

## Straddler Notes

SCB split is not a generic relation-authoring surface. It is provider triage that emits
two downstream conveniences: weak related edges for split siblings and fold hints for
slug generation. Treat those outputs explicitly and keep the SCB-specific identity
decision local.

SCB source-column identity repair is a real pre-state phase, not a relation layer.
`[[column_merge]]` normalizes never-co-occurring era-rename columns before union-find
connectivity mints variables; `[[fold_override]]` forces contested same-edition columns
into one fold cluster before final states exist. Both live in
`reg_meta_build/curation/scb/source_column_repairs.toml` — not `input_data/SCB/` source
data and not a broad `repair.toml`. `same_as` cannot substitute for either without first
creating the wrong variables, slugs, aliases, and state history.

Classification links are typed value/coding overrides. They target the
`classification_candidate` pipeline and then `variable_state.classification_id`; they
are not evidence for an arbitrary `variable_state_overrides.toml`. If this surface is
simplified, keep the operation typed as a classification assignment override with its
own validation and precedence.

Concept groups straddle derived relations and curated presentation. They should move
toward an explicit set subtype, not into tags and not into pairwise relations. The
edge-derived groups can be regenerated; the curated groups are authorial browse
decisions.

Delivery enrichment also straddles two meanings. Description backfills are source
gap-fill. Alias rows can affect delivery-column resolution. Keep the file separate
unless a future child proves that splitting descriptions from aliases makes maintenance
materially clearer.

Monthly families are the strongest deletion candidate. They solve a real monthly-column
ergonomics problem, but they currently solve it by mutating variable identity. Do not
abstract that mutation; reverse it when month-member sets and consumers can preserve the
intended selection behavior.

Event-derived and curated `replaced_by` should remain distinct inputs. The event-derived
path is a source fact, includes variant-grain succession, and has best-effort skips for
noisy SCB history. Curated `replaced_by` is human-authored directional lineage over FQID
slugs. They can share DB insertion, cycle checks, and traversal helpers, but the
authoring surfaces should not be merged.
